1서비스 개요

스트리머 인생게임은 SOOP 스트리머를 주인공 삼아, 유저가 0세부터 100세까지 그 인생을 3지선다로 대신 살아보는 인터랙티브 소설(생애 시뮬레이션) 웹게임입니다. 실제 스트리머 본인과는 무관한 가상의 인생이며, 매 선택이 재산·인기·행복·건강·관계 다섯 스탯을 흔들고 그 조합이 100세 시점의 엔딩을 정합니다.

  • 플랫폼: 단일 페이지 웹앱 (Vanilla JS + Firebase, 정적 호스팅 / GitHub Pages)
  • 대상: 스트리머 팬덤 커뮤니티, 익명 방문자 포함 누구나 즉시 참여 가능
  • 수익 모델: v1은 완전 무료 — 추후 보상형 광고("다시 태어나기" 등)·후원형 광고 추가 예정
  • 공유 인프라: StreamBet-Market·soop-stock-market·interior-3d-viewer와 동일한 Firebase 프로젝트(soop-stock-market)를 그대로 사용 — 스트리머 이름 검색에 필요한 stocks 노드를 새 프로젝트 없이 바로 읽기 위함

2핵심 컨셉

🔍 진짜 데이터로 짓는 이름

새 데이터를 따로 안 모으고, 이미 상장돼 있는 stocks 노드에서 이름을 검색해 주인공을 정합니다.

🎲 서버가 쥔 정답표

클라이언트는 고른 선택지 id만 보낼 뿐, 스탯 반영·엔딩 판정은 전부 서버에서 계산합니다 — 위변조도, 문장만 보고 결과를 미리 아는 것도 불가능합니다.

📖 "다른 유저는 어떤 인생을 살았을까?"

완료한 인생을 공개 갤러리에 공유할 수 있는 구조로, 처음부터 갤러리 열람을 핵심 화면으로 둡니다.

3화면 구성 (UI)

단일 페이지 안에서 아래 단계가 한 번에 한 화면만 보이도록 순서대로 나타납니다(다른 단계는 전부 숨김). 상단엔 다른 자매 프로젝트들과 동일한 devbar(교차 홍보 바)가 항상 떠 있습니다.

구획DOM id내용
⓪ 이어하기(조건부)#resumeSection로그인 직후 저장 슬롯을 확인해, 끝내지 않은 인생이 있으면 검색 대신 이 화면부터 보여줌 — "이어하기"/"새로 시작하기"
① 스트리머 검색#searchSectionstocks 검색 입력창 + 결과 목록. 클릭하면 이름이 다음 단계로 넘어감
② 이름 짓기#nameSection검색한 이름을 프리필해서 보여주고, 수정 후 "인생 시작"
③ 생애 진행#gameSection구간명/나이, 구간 스토리 문구, 3지선다 버튼, 선택 후 결과 텍스트 + 스탯 바
④ 엔딩#endingSection엔딩 제목/텍스트 + 최종 스탯, "갤러리에 공유하기"/"다시 태어나기"
⑤ 공개 갤러리#gallerySection다른 유저가 공유한 인생 목록 (실시간 구독, 최신순)

게임이 시작되면 상단 헤더(#mainHeader — eyebrow·제목·소개 문구)를 숨긴다. 대신 각 구간의 STAGES[].intro(1~2문장짜리 장면 설명, publicStage()가 그대로 전달)를 #gameSection 안 #storyText에 채워 "지금 어떤 이야기 안에 있는지"를 매 구간 새로 알려준다. 헤더는 게임 시작(startBtn)·이어하기(resumeBtn, 미완료 인생)·엔딩(showEnding) 세 지점에서 숨겨지고, 검색·이름짓기·이어하기 확인 화면에서는 그대로 보인다.

스탯 바는 스탯마다 다른 색으로 채워진다. 채움 너비는 항상 stats[key] 값 그대로(예: 50이면 50%), 색은 재산=골드·인기=코랄·행복=로즈·건강=세이지·관계=스카이로 고정 매핑 (STAT_COLORS). 선택지를 확정하면(직접 클릭이든 주사위든) 고르지 않은 나머지 선택지는 불투명도 30%로 흐려진다. 주사위 구간도 서버가 돌려준 choiceId로 어떤 미리보기가 뽑혔는지 표시하므로 동일하게 동작한다(markSelectedChoice()).

4생애 사이클 · 스탯 시스템

생애 10구간

균등한 나이 간격이 아니라 실제 인생의 결절점(입학·진로·독립·가정) 기준. 구현됨 3구간, 콘텐츠 미작성 7구간 — 형식은 동일해서 functions/game-data.js의 STAGES 배열에 이어 채우면 됨.

유아기는 예외 — 3지선다가 아니라 🎲 주사위 굴리기. 태어날 집안은 스스로 고를 수 있는 게 아니라는 취지로, STAGES의 infancy에만 random: true를 붙였다. 클라이언트는 선택지를 클릭 불가능한 미리보기로만 보여주고 "🎲 주사위 굴리기" 버튼 하나만 누를 수 있으며, 서버(rollDice)가 3개 중 하나를 균등 확률로 직접 뽑아 반영한다 — submitChoice는 random 구간을 아예 거부해서 클라이언트가 직접 골라 우회할 수 없다.

주사위 굴리기를 누르면 결과가 바로 나오지 않는다. 화면 전체가 어두워지며 (#diceOverlay) 주사위 아이콘이 회전하는 연출이 최소 3초(DICE_REVEAL_MS) 보여진 뒤에야 결과가 공개된다 — 서버 응답이 3초보다 빨리 와도 최소 3초는 채우고, 응답이 더 늦어지면 그만큼 더 기다린다(Promise.all로 연출 타이머와 서버 호출을 함께 기다림). 실제 당첨 결과는 언제나 서버가 이미 결정해 응답에 담아 보낸 상태이며, 연출은 순수하게 클라이언트 쪽 대기 시간일 뿐 서버 로직에는 영향이 없다.

엔딩은 스탯 5개 조합의 최근접 아키타입 매칭(resolveEnding) — 이후 12~16종으로 늘릴 땐 ENDINGS 배열에 항목만 추가하면 되고 매칭 로직은 그대로다.

5선택지 작성 원칙

선택지 문장만 보고 결과를 예측할 수 없어야 한다. deltas·result는 서버(functions/index.js의 publicStage())가 선택 전엔 절대 클라이언트로 보내지 않는다 — 개발자 도구로 응답을 뜯어봐도 안 보임.

지양 — 결과가 문장에 이미 있음

  • "안정적인 대기업에 입사한다 (+재산, −인기)"
  • "위험을 감수하고 창업한다 (재산 ±큰 변동)"

지향 — 태도만 드러냄

  • "다니던 학교를 관두고 방송을 시작해본다"
  • "바로 돈이 되는 기술을 배워 취업 전선에 뛰어든다"

세 선택지는 항상 안전 / 도전 / 우회 세 태도 중 하나에 가깝게 쓴다 — 매번 다른 톤을 새로 짜내는 대신, 이 뼈대 위에서 구간별 소재만 갈아 끼운다.
